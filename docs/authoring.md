# ساخت فایل ارائه با هوش مصنوعی

این سند قالب JSON ارائه را می‌گوید تا یک مدل زبانی بتواند بدون دانستن کد برنامه،
یک فایل `.json` بسازد که با «ورودی JSON» در استودیو پذیرفته شود.

### سؤال‌ها

```json
[{
  "id": "q-1404-01",
  "stem": "اگر $x_1 = ۶$ و $x_2 = -۴$ باشد، جابه‌جایی چقدر است؟",
  "options": ["$۱۰$", "$-۱۰$", "$۱۶$", "$۲$"],
  "answerIndex": 1,
  "difficulty": 3,
  "tags": ["کنکور:حرکت‌شناسی:جابه‌جایی"],
  "source": "کتاب درسی",
  "year": 1404,
  "explanation": "جابه‌جایی اختلاف است: $-۴ - ۶ = -۱۰$.",
  "answerKey": {
    "title": "راه‌حل گام‌به‌گام",
    "steps": [
      { "kind": "text", "span": "full", "value": "**گام ۱:** مبدأ را روی صفر بگذارید." },
      { "kind": "formula", "span": "half", "value": "\Delta x = x_2 - x_1 = -4 - 6" },
      { "kind": "callout", "span": "half", "tone": "warn", "value": "دام: مسافت $۱۰$ است، نه جابه‌جایی." }
    ]
  }
}]
```

* `difficulty` از **۱ (خیلی آسان)** تا **۵ (خیلی سخت)**.
* `answerKey` یک **اسلاید** است: `steps` همان union کادرهای بخش ۴ است، پس
  می‌توانید انیمیشن هم بگذارید. در اجرا بعد از پاسخ دادن، دکمهٔ «پاسخ‌نامهٔ
  تشریحی» ظاهر می‌شود.
* برای ویرایش و پیش‌نمایش دسته‌ای، این JSON را در `/bank/import` بچسبانید.

مرجع **قطعی و کامل** همهٔ میدان‌ها، مقادیر مجاز و رفتار خطاها در
[`api.md`](api.md) است؛ این فایل نسخهٔ کاربردی و کوتاه‌تر همان است.

مسیر ورود: استودیو → جعبه‌فرمان (`Ctrl/⌘ + K`) → «ورودی JSON…»، یا دکمهٔ
«ورودی JSON» کنار دکمهٔ تکثیر در پایین ستون کناری.

## ۱. قوانین کلی (این‌ها را نقض نکنید)

۱. **یک شیء، یک ارائه.** بالاترین سطح یا یک شیء ارائه است یا آرایه‌ای از
   ارائه‌ها. آرایه یعنی «چند ارائه در یک فایل».
۲. **`slides` باید آرایهٔ خالی‌نباشد.** اگر نباشد یا خالی باشد، فایل
   «معتبر نیست» گزارش می‌شود و چیزی وارد نمی‌شود.
۳. **`id` را خودتان بسازید و یکتا بگذارید.** اگر `id` نباشد برنامه یکی
   می‌سازد، ولی اگر `id` تکراری باشد ارائهٔ قبلی **بازنویسی** می‌شود.
   برای فایل تولیدشده توسط AI از الگوی `ai-<موضوع>-<تاریخ>` استفاده کنید.
۴. **شناسهٔ کادرها یکتا باشد** (در کل فایل، نه فقط در یک بخش). `steps` و
   `layers` و `series` شناسه می‌خواهند چون کلید ارجاع‌اند.
۵. **زبان همهٔ متن‌ها فارسی است.** اعداد را انگلیسی بنویسید (`2` نه `۲`) مگر
   داخل فرمول یا متن؛ برنامه خودش اعداد را فارسی نمایش می‌دهد.
۶. **چیزی را که نمی‌شناسید حذف نکنید.** فیلد ناشناخته بی‌اثر است و
   `kind` ناشناخته به متن ساده تبدیل می‌شود — محتوای شما گم نمی‌شود، ولی
   ظاهرتش را هم از دست می‌دهد. پس `kind` را از فهرست بند ۴ بردارید.
۷. **یک ارائه را کامل بسازید.** ارائهٔ نیمه‌کاره با بخش‌های خالی، در
   ارائه‌دهی بد به‌نظر می‌رسد.

## ۲. اسکلت ارائه

```json
{
  "schema": 2,
  "id": "ai-kinematics-1404",
  "title": "حرکت‌شناسی — از مکان تا شیب نمودار",
  "description": "یک خط توضیح کوتاه که در فهرست ارائه‌ها دیده می‌شود.",
  "theme": "light",
  "layout": "flow",
  "createdAt": 1750000000000,
  "updatedAt": 1750000000000,
  "slides": []
}
```

| میدان | لازم؟ | مقدار |
| --- | --- | --- |
| `schema` | نه | عدد `2`. برنامه خودش می‌نویسد. |
| `id` | نه | رشتهٔ یکتا. |
| `title` | نه | اگر نباشد «بدون عنوان». |
| `description` | نه | متن کوتاه. |
| `theme` | نه | `light` \| `dark` \| `paper` — پیش‌فرض `light`. |
| `layout` | نه | `flow` \| `stack` — پیش‌فرض `flow`. |
| `createdAt` / `updatedAt` | نه | میلی‌ثانیه. اگر نباشد «الان». |
| `slides` | **بله** | آرایهٔ بخش‌ها. |

`layout` مهم است: در `flow` عرض هر کادر (`span`) رعایت می‌شود و کادرهای
`half`/`third` کنار هم می‌نشینند؛ در `stack` همه چیز تمام‌عرض است. برای
ارائه‌های آموزشی `flow` بهتر است.

## ۳. بخش‌ها

```json
{

  "title": "علامت کمیت‌ها",
  "notes": "یادداشت معلم: قبل از شروع بپرس «مکان مثبت یعنی سمت راست؟».",
  "steps": []
}
```

| میدان | لازم؟ | توضیح |
| --- | --- | --- |
| `id` | نه | یکتا در کل فایل. |
| `title` | نه | عنوان بخش؛ در حالت ارائه بالای صفحه می‌آید. |
| `notes` | نه | یادداشت معلم. در اجرا با کلید `N` (یا دکمهٔ یادداشت) نمایش داده می‌شود و در چاپ نمی‌آید. |
| `steps` | **بله** | آرایهٔ کادرها؛ می‌تواند خالی باشد ولی بهتر نباشد. |

## ۴. کادرها (steps)

هر کادر سه میدان مشترک دارد:

```json
{ "kind": "text", "span": "full", "id": "k-intro", "value": "…" }
```

* `kind` — یکی از فهرست زیر. **تنها میدانی که نوع کادر را تعیین می‌کند.**
* `span` — عرض در شبکهٔ ۶ ستونی: `full` (۶ ستون)، `half` (۳ ستون)،
  `third` (۲ ستون). اگر حذف شود، برنامه بر اساس `kind` یک عرض پیش‌فرض
  می‌گذارد (متن و پرسش تمام‌عرض، فرمول و فهرست نصف، کادر رنگی یک‌سوم).
* `id` — یکتا در کل فایل.

عرض‌ها جمع شونده‌اند: `full` + `full` دو ردیف می‌شود؛ `half` + `half` یک ردیف؛
`third` + `third` + `third` یک ردیف. برای ردیف کامل، عرض‌ها باید ۶ شوند.

### جدول کادرها

| `kind` | میدان‌های خاص | کاربرد |
| --- | --- | --- |
| `text` | `value` | پاراگراف؛ `**پررنگ**`، `*مورب*`، `` `کد` ``، `==هایلایت==`، `$x = vt$`، URL خام. |
| `list` | `items: string[]`, `ordered?: boolean` | فهرست نکته‌ها؛ `ordered: true` یعنی شماره‌دار. |
| `formula` | `value` | فرمول LaTeX **تمام‌عرض و بزرگ**. بین `$` ننویسید. |
| `callout` | `value`, `tone` | کادر رنگی. `tone`: `info` \| `tip` \| `warn` \| `idea`. |
| `trap` | `value` | «دام رایج» — همان چیزی که دانش‌آموز اشتباه می‌کند. |
| `image` | `value` (آدرس), `alt?`, `caption?` | تصویر از URL. |
| `video` | `value` (آدرس), `caption?` | یوتیوب، آپارات، Vimeo، یا فایل `mp4/webm`. |
| `code` | `value`, `caption?` | قطعه کد با دکمهٔ کپی. |
| `quiz` | `question`, `options: string[]`, `answerIndex: number`, `explanation?` | پرسش چهارگزینه‌ای. |
| `animation` | `anim` (بند ۶) | صحنهٔ زنده با نمودار و حرکت. |

### متن درون‌خطی

هر `value` متنی از این نشانه‌ها را می‌فهمد — و **هیچ Markdown دیگری** نه:
عنوان `#`، فهرست `-`، جدول و بلوک کد پشتیبانی نمی‌شوند.

```
**پررنگ**     *مورب*     `کد`     ==هایلایت==     $x = v_0t - ۱۲ t^2$
https://example.com/img.png
```

فرمول درون‌خطی بین `$...$` است و با KaTeX رندر می‌شود؛ خط جدید در متن
یعنی `<br>`.

### نمونهٔ چند کادر

```json
{ "steps": [
  { "id": "k1", "kind": "text", "span": "full",
    "value": "**مکان** مکانِ محور را با علامت توصیف می‌کند: $x = -۴$ یعنی چهار متر سمت **منفی**." },
  { "id": "k2", "kind": "formula", "span": "half", "value": "\\Delta x = x_2 - x_1" },
  { "id": "k3", "kind": "callout", "span": "half", "tone": "warn",
    "value": "دام: جابه‌جایی هیچ‌وقت منفی نمی‌شود، حتی وقتی $\\Delta x < 0$ است." },
  { "id": "k4", "kind": "list", "span": "full", "ordered": true,
    "items": ["مبدأ را انتخاب کن", "علامت را گم نکن", "واحد را بنویس"] },
  { "id": "k5", "kind": "trap", "span": "third",
    "value": "«مسافت» و «جابه‌جایی» را قاطی نکنید." },
  { "id": "k6", "kind": "quiz", "span": "third",
    "question": "اگر $x_1 = ۶$ و $x_2 = -۴$ باشد، جابه‌جایی چقدر است؟",
    "options": ["$۱۰$", "$-۱۰$", "$۱۶$", "$۲$"],
    "answerIndex": 1,
    "explanation": "جابه‌جایی اختلاف است: $-۴ - ۶ = -۱۰$." }
] }
```

### قواعد پرسش

* **۴ گزینه** بنویسید. محدودیت سختی وجود ندارد، ولی رابط کاربری تا
  ۸ گزینه اضافه می‌کند و کلیدهای پاسخ تا ۱۲ گزینه (`1`–`6` و `a`–`f`) کار
  می‌کنند؛ کمتر از ۲ گزینه پرسش نیست.
* `answerIndex` **صفر-پایه** است: `0` یعنی گزینهٔ اول. این مقدار هنگام
  ورود **اصلاح نمی‌شود**: اگر `answerIndex` بزرگ‌تر یا مساوی
  `options.length` باشد، هیچ گزینه‌ای درست نیست و دانش‌آموز هرچه بزند
  «اشکال ندارد» می‌شنود. حتماً بشمارید.
* `explanation` بعد از انتخاب دانش‌آموز نمایش داده می‌شود؛ توضیح بدهید
  **چرا**، نه اینکه چه چیزی درست است.
* گزینه‌ها باید هم‌سطح باشند: همهٔ عدد، یا همهٔ عبارت.

## ۵. کادر انیمیشن (نسخهٔ ۲)

هر انیمیشن نسخهٔ ۲ یک سند مستقل است. دستور `schema: 2` آن را از نسخهٔ ۱ جدا می‌کند؛
نسخهٔ ۱ هنوز خوانده می‌شود و خودکار ارتقا می‌یابد.

```json
{
  "id": "k-anim-1",
  "kind": "animation",
  "span": "full",
  "anim": {
    "schema": 2,
    "title": "جابه‌جایی روی محور",
    "duration": 6,
    "params": { "v": { "value": 4, "min": 0, "max": 20, "slider": true, "label": "سرعت" } },
    "cues": [{ "t": 3, "label": "اینجا متوقف شو", "pause": true }],
    "nodes": [
      {
        "id": "frame",
        "type": "axes",
        "axes": { "xDomain": [0, 6], "yDomain": [0, 20], "rect": [0.07, 0.06, 0.9, 0.8],
                  "ticks": { "x": 6, "y": 4 }, "labels": { "x": "t (s)", "y": "x (m)" } },
        "children": [
          { "id": "curve", "type": "plot", "transform": {}, "expr": "v*t", "domain": [0, 6],
            "style": { "stroke": "#111827", "strokeWidth": 3, "trim": { "expr": "clamp(lt/3, 0, 1)" } } },
          { "id": "body", "type": "ellipse", "transform": { "x": { "expr": "v*t" }, "y": { "expr": "v*t" } },
            "shape": { "rx": 8, "ry": 8 }, "style": { "fill": "#f97316" } }
        ]
      }
    ]
  }
}
```

### ۵.۱ — سه چیزی که هر انیمیشن v2 دارد

| چیز | معنی |
| --- | --- |
| `nodes` | همه‌چیز. هر شکل، منحنی، برچسب و محور یک `node` است. |
| `transform` | روی هر گره هست: `x, y, scaleX, scaleY, rotation, opacity` |
| `style` | `fill, stroke, strokeWidth, dash, trim` — `trim` یعنی «چقدر از خط کشیده شده» |

هیچ میدانی به نام سرعت، شتاب یا خط مماس وجود ندارد. آن‌ها **قالب** هستند
(§۵.۶)، نه ویژگی موتور. یک فصل تازه، یک قالب تازه می‌خواهد؛ نه تغییر موتور.

### ۵.۲ — سه حالت برای هر عدد

هر `transform` و هر ویژگیِ قابل انیمیشن، یکی از این سه است:

```jsonc
"x": 3                              // ثابت
"x": { "expr": "4*t - 2*t*t" }      // فرمول
"x": { "keys": [                    // کی‌فریم
      { "id": "a", "t": 0, "v": 0, "ease": "smooth" },
      { "id": "b", "t": 2, "v": 10, "ease": "easeOut" }
] }
```

`ease` می‌تواند `linear | ease | easeIn | easeOut | hold | smooth` باشد یا یک
رشتهٔ `cubic-bezier(a,b,c,d)`.

> `ease` در v2 همان **م quadratی** نسخهٔ ۱ است، نه `cubic-bezier` هم‌نام CSS.
> این عمدی است: ۲۳ انیمیشن موجود در محصول به آن وابسته‌اند و عوض‌کردنش
> سرعت همه‌شان را تغییر می‌دهد. اگر منحنی CSS می‌خواهید، بنویسید
> `cubic-bezier(0.25, 0.1, 0.25, 1)`.

`smooth` (PCHIP یکنوا) مشتق بسته‌فرم دارد — به همین دلیل نمودار شتاب
که از کی‌فریم ساخته می‌شود در مرز کی‌فریم‌ها جهش نمی‌کند.

### ۵.۳ — زمان بندی: `lt`

هر گره می‌تواند پنجرهٔ زمانی داشته باشد. `lt` زمان **محلی** است: از لحظهٔ شروع
گره صفر می‌شود.

```json
{
  "id": "curve", "type": "plot", "expr": "x*x",
  "time": { "start": 1.5, "end": 4.5 },
  "style": { "trim": { "expr": "clamp(lt/3, 0, 1)" } }
}
```

این همان چیزی است که در نسخهٔ ۱ با `reveal: boolean` ممکن نبود: نموداری که
**دیرتر** ظاهر می‌شود و **مدت مشخصی** طول می‌کشد.

### ۵.۴ — ارجاع بین گره‌ها

`@id.prop` مقدارِ همان لحظهٔ یک گره دیگر را می‌خواند. `@plot.at(x)` مقدار یک
منحنی را در یک `x` می‌دهد.

```json
{ "id": "follower", "type": "ellipse",
  "transform": { "x": { "expr": "@body.x + 10" }, "y": 0 } }
```

ارجاع‌های حلقوی (`a` به `b` و `b` به `a`) در زمان کامپایل تشخیص داده می‌شوند؛
آن گره‌ها صفر در نظر گرفته می‌شوند و یک هشدار می‌دهند. **هرگز خطا نمی‌اندازند.**

### ۵.۵ — زبان فرمول

متغیرها: `t` (ساعت صحنه)، `lt` (زمان محلی)، `x` (متغیر محور داخل نمودار)،
`u` (پارامتر منحنی)، `duration`، و هر نامی که در `params` یا `exprParams` باشد.

عملگرها: `+ - * / % ^` (توان راست‌شرکت‌پذیر)، `< > <= >= == !=`، `&& || !`،
و **ضرب ضمنی**: `2t`، `3(t+1)`، `2pi`، `(a)(b)`.

توابع:
`sin cos tan asin acos atan sinh cosh tanh sqrt abs exp ln log log2 log10 floor
ceil round trunc frac sign mod pow min max hypot atan2 deg rad clamp lerp
smoothstep step if dist dot len d`

```jsonc
"if(r < 2, 1, 0)"      // شرط، به‌جای if کلیدواژه
"clamp(t, 0, 1)"
"d(4*t - 2*t*t)"       // مشتق نسبت به t — یعنی سرعت
"atan2(vy, vx)"        // رادیان
"deg(atan2(vy, vx))"   // درجه؛ rotation همیشه درجه است
```

`d()` نمادی است: `d(4*t - 2*t*t)` دقیقاً `4 - 4*t` می‌دهد، نه یک تفاضل
تقریبی. روی ارجاع‌ها به تفاضل مرکزی برمی‌گردد.

نام‌های رزرو‌شده که نمی‌توانید به‌عنوان متغیر تعریف کنید:
`t, lt, x, u, duration, time, زمان, pi, e, tau, phi, true, false, if` و نام
همهٔ توابع.

### ۵.۶ — قالب‌ها

قالب یک زیردرخت معمولی است. کتابخانهٔ آماده:

`velocityArrow`، `accelerationArrow`، `positionVector`، `accelDecomposition`،
`tangentLine`، `secantLine`، `averageWindow`، `motionTrail`، `valueReadout`،
`graphReveal`، `forceArrow`، `inclinePlane`، `freeBodyDiagram` (با لغزندهٔ θ)،
`springOrBlock`.

```json
{ "id": "fbd", "type": "use", "template": "freeBodyDiagram",
  "transform": { "x": 100, "y": 50 },
  "props": { "rotation": { "expr": "deg(t)" } } }
```

`props` روی هر ویژگیِ `transform` قالب بازنویسی می‌شود.

### ۵.۷ — محور و پنل

`axes` یک کادر مختصات است و فرزندانش در **واحدهای دادهٔ** آن مکان می‌گیرند.
چند `axes` در یک صحنه = چند پنل که یک ساعت را به اشتراک می‌گذارند.

`rect` کسری از کادر صحنه است: `[0, 0, 1, 1]` یعنی تمام صحنه،
`[0, 0, 1, 0.5]` یعنی نیمهٔ بالا. کمی حاشیه بگذارید تا جای تیک و برچسب محور
بنشیند: `[0.07, 0.06, 0.9, 0.8]`.

### ۵.۷٫۱ — متغیرها، شرط‌ها و ذرات

**متغیرها** (`vars`) کمیت‌های مشتق را یک بار می‌نویسید و هرجا لازم بود
می‌خوانید. ترتیب نوشتن مهم نیست؛ موتور وابستگی‌ها را خودش مرتب می‌کند و
اگر چرخه‌ای بسازد، به‌جای عدد غلط، هشدار می‌دهد.

```json
"vars": {
  "r2": "(x2 - x1)^2",
  "F": "9e9 * q1 * q2 / max(r2, 0.01)"
}
```

**شرط‌ها** (`events`) روی **لبهٔ صعودی** اجرا می‌شوند: در همان فریمی که شرط
درست می‌شود، نه در تمام فریم‌هایی که درست است. این تفاوت مهم است — وگرنه
ذرات شما در هر فریم زاده می‌شدند.

```json
"events": [{
  "id": "spark", "when": "r < 1.5", "once": true,
  "actions": [{ "type": "spawnParticles", "at": ["(x1+x2)/2", "0"],
    "count": 20, "color": "#fbbf24", "speed": 3, "lifetime": 0.8 }]
}]
```

نقطهٔ `at` در **واحدهای خودِ صحنه** است، پس اگر `axes` داشته باشید روی همان
محور می‌افتد. ذرات سقف دارند و بیرون از بوم کشیده نمی‌شوند.

### ۵.۷٫۲ — رسم‌ها

رسم‌ها (`drawings`) زیر گره‌ها کشیده می‌شوند: پیکان، اندازه،/protractor و
برچسب. چون تزئین‌اند، دستگیرهٔ انتخاب و کادر ندارند — یک نیروی دست‌کشیده
نباید در تایم‌لاین جعبه داشته باشد.

```json
"drawings": [
  { "id": "F", "kind": "arrow", "label": "F",
    "from": { "x": "(x1+x2)/2", "y": 0 },
    "to":   { "x": { "expr": "(x1+x2)/2 + F*0.001" }, "y": 0 },
    "style": { "stroke": "#dc2626", "width": 2 } }
]
```

مختصات‌ها فرمول می‌پذیرند، پس پیکان نیرو می‌تواند جسم متحرک را دنبال کند.

### ۵.۷٫۳ — لنگرها

`anchors` نقطه‌های اتصال نام‌دار روی گره است، در واحدهای خودِ گره و **پیش از**
چرخش. از آن‌ها با `@id@name.x` و `@id@name.y` یاد می‌شود:

```json
{ "id": "bob", "type": "ellipse", "r": 2,
  "anchors": { "top": { "x": 0, "y": "-r" } } }
```

```json
{ "expr": "sqrt((@bob@top.x - px)^2 + (@bob@top.y)^2)" }
```

لنگر با چرخش گره می‌چرخد، پس قلاب روی آویزانِ در حال نوسان می‌ماند.

### ۵.۷٫۴ — کنترل‌ها

`params` فقط عدد نیست: هر کنترلی که بسازید همان یک عدد را می‌نویسد، پس
فرمول شما فرقی نمی‌کند.

```json
"params": {
  "q":   { "value": 2, "min": 1, "max": 8, "slider": true },
  "show": { "value": 0, "control": "toggle" },
  "mode": { "value": 0, "control": "select", "options": ["شبیه‌سازی", "واقعیت"] },
  "go":   { "value": 0, "control": "button", "pulseFor": 0.4,
            "actions": [{ "type": "resume" }] }
}
```

شرط‌ها روی همان عددها نوشته می‌شوند: `when: "show == 1"`.

### ۵.۷٫۵ — شکل‌ها

`shapes` نام‌هایی است که گره `shape` می‌کشد. مسیر در `w`, `h`, `r`, `a`, `n`
می‌نویسد و هر گره می‌تواند پارامترهایش را عوض کند:

```json
"shapes": { "ramp": { "path": "M -w/2 -h L w/2 -h L w/2 h L -w/2 h Z",
                      "params": { "w": 6, "h": 1 } } },
"nodes": [{ "id": "s", "type": "shape", "shape": "ramp",
            "params": { "h": { "expr": "sin(t)*0.3 + 0.5" } }, "...": "..." }]
```

شکل‌های آماده: `wedge`, `ramp`, `box`, `disc`, `disc-sector`, `arrowhead`,
`cone-half`.

### ۵.۷٫۶ — پخش بخش‌بندی‌شده

```json
"playback": {
  "segments": [{ "id": "setup", "from": 0, "to": 4 },
               { "id": "ask",   "from": 6, "to": 9 }],
  "pingPong": false, "startAt": 0, "stopAt": 9
}
```

بخش‌های هم‌پوشان ادغام می‌شوند و بازه‌های وارونه جابه‌جا، پس یک ویرایش دستی
ساعت را گیر نمی‌اندازد. `pingPong` برای نوسان طبیعی است.

### ۵.۸ — زاویه‌ها و مختصات

* زاویه‌ها **درجه** و پادساعت از محور x هستند: `0` راست، `90` بالا،
  `−90` پایین.
* صحنهٔ آزاد مختصات بوم دارد: `y` رو به پایین می‌رود، مثل SVG.
* داخل `axes` دامنهٔ y برعکس می‌شود، پس کاری که می‌نویسید شبیه نمودار است.

### ۵.۹ — چهار دام که وقت می‌گیرد تا پیدا شود

۱. **جسم لنگر را `follow` نکنید.** در v2 ارجاع `@plot.at(t)` یعنی «روی
   منحنی، با `x` برابر ساعت». برای یک لحظهٔ ثابت بنویسید:
   `"x": "2"`, `"y": "0.5*2^2 - 2*2 + 4"`.

۲. **فرمول فاصله را با زمان‌بندیِ متن بخوانید.** `"max(0, 3.5 - t)"` یعنی
   فاصله در ۳٫۵ ثانیه صفر می‌شود، نه اینکه از ۳٫۵ به بعد کم شود. اگر می‌خواهید
   بین ۳٫۵ تا ۷ کم شود:
   `"dt": "max(0, 2.2 - (2.2/3.5)*max(0, t - 3.5))"`.

۳. **وقتی دو نقطه روی هم می‌افتند پاره‌خط عملاً ناپدید می‌شود.** این همان درس
   «قاطع ← مماس» است؛ اگر می‌خواهید مماس *بماند*، جدا به‌عنوان پاره‌خط یا
   منحنی با `time` خودش بسازید.

۴. **شفافیت دستی ننویسید.** به‌جای ساختن چند نسخهٔ یک عنصر و کی‌فریم‌کردن
   `opacity`، از `time` و `trim` استفاده کنید تا همان عنصر سر وقت خودش ظاهر شود.

### ۵.۱۰ — کار کردن با اسنود قدیمی

`migrateAnimationV1toV2` هنگام بارگذاری خودکار اجرا می‌شود. لایهٔ کلیدی → گره
با `transform` کی‌فریم‌دار؛ لایهٔ فرمولی → `transform` با `{expr}`؛
لایهٔ `follow` → `y = @series.at(t)`؛ سری → `plot`؛ `reveal` → `style.trim`؛
پنل‌ها → چند `axes`.

**نکتهٔ مهم:** فرمول سری‌های v1 تابعی از **زمان** بود و در v2 فرمول نمودار تابعی
از **x** است. مهاجرت این را خودکار بازنویسی می‌کند (از طریق توکن‌ساز، نه
`replace`، تا `dt` و `atan2(t)` خراب نشوند). اگر دستی می‌نویسید، یادتان باشد
`t` را به `x` تبدیل کنید.

## ۶. ساختار پیشنهادی یک ارائهٔ خوب

```
۱. نقشهٔ راه        text + list(شماره‌دار) + callout(idea)     ← بدون انیمیشن
۲. تعریف کمیت      text + formula + trap
۳. رابطهٔ کمیت‌ها   formula + animation
۴. نمودارها         animation (با tangent/secant)
۵. روش حل          callout(tip) + code یا video
۶. جمع‌بندی         text + quiz
```

قواعد تجربی که در عمل جواب داده‌اند:

* **هر بخش ۳ تا ۶ کادر** داشته باشد؛ بیشتر از آن در یک صفحه جا نمی‌شود.
* **حداکثر یک انیمیشن در هر بخش.** دو انیمیشن پشت‌سرهم یعنی صفحهٔ شلوغ.
* **در بخش تعریف، انیمیشن نگذارید.** اول مفهوم، بعد تصویر.
* **حداقل یک `quiz` در انتهای هر درس** بگذارید، ولی نه در هر بخش.
* **`notes` را جدی بگیرید**: جایی که باید مکث کنید یا سؤال بپرسید.
* **`text` را بیشتر از ۴ خط نکنید.** متن بلند یعنی ارائه‌دهنده می‌خواند.
* **پرسش‌ها را آخر بخش بگذارید، نه وسط جمله‌ها.**

## ۹. نکته‌های رفتاری که ممکن است غافلگیرتان کند

* **ورود، ادغام است نه جایگزینی.** فایل جدید به ارائه‌های موجود اضافه
  می‌شود؛ فقط ارائه‌ای که `id` یکسان داشته باشد بازنویسی می‌شود. برای
  همین `id` یکتا مهم است.
* **داده در مرورگر است.** اگر کاربر حالت خصوصی یا مرورگر دیگری باز کند،
  ارائه‌ها را نمی‌بیند. برای پشتیبان، از دکمهٔ «خروجی» JSON بگیرید.
* **`formula` تمام‌عرض است.** فرمول‌های کوتاه را در `text` بین `$...$`
  بنویسید تا کنار متن بنشینند.
* **انیمیشن در اجرا خودکار پخش می‌شود** اگر `autoplay: true` باشد؛ در
  ویرایشگر با `Space` کنترل می‌شود.
* **متن انیمیشن (`title`) بالای صحنه** می‌آید و در فهرست کادر دیده می‌شود.
